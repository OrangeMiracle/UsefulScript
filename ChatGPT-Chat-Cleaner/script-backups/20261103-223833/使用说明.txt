ChatGPT Windows 残留 Chat 目录清理器（手动运行）

使用
1. 保持 ChatGPT 桌面版打开，在资源管理器中双击 Clean.cmd。
2. 脚本先只读检查。只有当前客户端日志在最近2小时明确返回 conversation_deleted，且进程、账号和正在使用的数据库均能匹配，才会关闭客户端、备份、事务清理并重开。
3. 若提示没有安全目标，脚本没有删除任何记录。可在桌面版手动点开你确定已删除的残留聊天，等它报错，再运行 Clean.cmd。不要批量打开或反复刷新。
4. 只想查看候选，双击 Audit.cmd。回滚本工具最近一次成功清理，双击 Rollback-Last.cmd。

重要限制
这是“根据客户端新鲜明确证据清理本地缓存”，不是自动扫描所有云端会话。脚本没有服务器认证/删除接口，不读取凭据、不发送网络请求，因此不会重演此前批量读取历史触发429的行为，也不需要sleep来节流。
普通404、加载失败、列表缺失、missing_candidate、归档、429均不授权删除。近期日志出现429时，本次只报告。
账号绑定来自当前客户端进程实体日志的唯一通知身份标识；缺失或多账号歧义时只报告，可能无法自动处理某些真实残留。不要通过删掉校验来强制清理。
两套目录库都会审计，只修改能确认由当前客户端占用的唯一库。未识别的schema或多个活动库会拒绝写入。
客户端更新后若数据库结构变化，需要重新审查并更新schema适配文件，不要自行刷新白名单后直接执行。
本工具只适配本机已检查的OpenAI.Codex Windows MSIX包及数据库结构。依赖已安装的Python 3.10+和Windows PowerShell，无第三方Python包、API key或管理员权限要求。
已有的每周审计任务不受本工具修改；本工具不新增计划任务。

安全和结果
真实清理会结束该桌面客户端的所有窗口和托盘进程，请先结束正在生成的回答、保存未发送内容。建议从资源管理器双击，避免从会随客户端退出的集成终端启动。
先用SQLite backup API生成一致性备份，再单事务逐行核对精确复合主键和完整原始记录。只删确认失效的ChatGPT目录行，catalog_revision增加1；其他记录及表的摘要必须不变，完整性检查必须通过。
不会删除云端聊天、本地Codex/Work任务、项目、凭据、会话正文文件、整个.codex目录或WAL/SHM文件。
只有出现SUCCESS，并且对应运行目录下post-restart.json状态为verified，才表示提交和重开后复核均成功。没有目标会报告只读完成，不会关闭客户端。
失败时查看run.jsonl、desktop.jsonl和对应*-stderr.txt。若已生成result.json，先查看其提交状态，不能把提交后的重启失败当成未提交。

备份与回滚
每次结果位于本文件夹下runs\<时间>-clean或-rollback。
audit.json：只读检查和候选；plan.json：精确目标和证据。
before.db：本次写入前的SQLite一致性备份；result.json：提交回执；post-restart.json：重开后复核。
Rollback-Last.cmd只恢复本工具最近一次成功清理的精确原始目录行，并先备份回滚前的当前库。目标已存在、结构变化或仍占用会整批拒绝，不覆盖后续正常数据。
本工具的回滚入口不处理此前聊天里其他目录中的历史修复；那些回滚脚本仍在各自原目录。
不要在客户端运行时直接覆盖数据库，不要删除WAL/SHM，也不要用整库恢复覆盖后续正常变更。
请保留整个工具文件夹；可整体移动，不要只复制一个cmd文件。

验证
本机Windows只读Audit实测成功，未退出客户端、未写入目录数据库、网络请求0。
6项临时SQLite/日志测试通过：精确删除与选择性回滚；目标行改变时整事务撤销；schema变化拒绝；本地任务拒绝；当前进程及唯一账号绑定；429和普通404拒绝。
此工具交付时没有再次真实清理用户数据库。
